# TerraPulse data and models

TerraPulse starts with three global catalogs and dated observations. The first buildable learning task is event-level flood mapping. The earthquake job is to measure surface displacement after an event. The glacier job is to show how ice mass, height and speed change over different time scales.

## Project setup and data export

1. Open the [Earth Engine Code Editor](https://code.earthengine.google.com/), sign in and use the account menu to select **Change Cloud Project**. Copy the project's **ID**, distinct from its display name or numeric project number. The Cloud project must be registered for Earth Engine and have the API enabled. See [Google's access requirements](https://developers.google.com/earth-engine/guides/access). In Python use `ee.Authenticate()` and `ee.Initialize(project=...)` with that same project ID.
2. Paste [the Guelma script](../scripts/earth_engine_guelma.js) into the editor. The first run prints the scene date, orbit, pass and ID for a fixed region and date window. A catalog hit is a footprint intersection. Inspect overlap and verify event timing before selecting a scene. If no suitable acquisition exists, use the NISAR catalog and keep the existing radar comparison as the public evidence.
3. Set `orbit` and `pass` to one geometry present in both windows. The script compares the first event-window acquisition to the median of the matching baseline, with common valid-pixel coverage, and shows preliminary darkening candidates. Review stable dry areas, reservoir water, urban pixels and shadow. For production, add radar-geometry masks, select a baseline earlier than the onset, and store the exact scene manifest. A slope mask alone cannot identify radar layover or shadow.
4. Enable `exportToDrive` and start the generated task only after reviewing the pair. It exports float features in UTM zone 32N at 30 m, with `-9999` NoData. Keep output rasters and acquisition manifests in object storage. Serve published layers as tiled imagery plus numeric assets for inspection. Earth Engine map IDs and their tile URLs belong to a rendering session. Train from scientific bands or samples exported with masks, units, CRS and dates.

An Earth Engine Cloud project controls computation and access. A collection ID identifies a published dataset. A CMR concept ID identifies a NISAR granule or collection. The Vercel map uses public NASA GIBS and bundled provider data, so visitors can load it without connecting a personal Google account.

## Meryem’s layers and the role of each dataset

| Dataset and Earth Engine bands | Measurement and preprocessing | Role in ML |
|---|---|---|
| [Sentinel-1 GRD](https://developers.google.com/earth-engine/datasets/catalog/COPERNICUS_S1_GRD) · `COPERNICUS/S1_GRD` · `VV`, `VH`, `HH`, `angle` | Backscatter is already in dB. Filter by AOI, date, mode, resolution, polarization, pass and relative orbit. Pair on common coverage. Polar HH can come from EW scenes, so check mode and coverage before selecting scenes. | Same-geometry baseline, event backscatter and change are flood-mapping features. Ice backscatter supplies context. Velocity needs matched features in a pair with known elapsed time. GRD omits phase needed for InSAR. |
| [ALOS PALSAR annual](https://developers.google.com/earth-engine/datasets/catalog/JAXA_ALOS_PALSAR_YEARLY_SAR_EPOCH) · `JAXA/ALOS/PALSAR/YEARLY/SAR_EPOCH` · `HH`, `HV` | Convert positive QA-valid DN to gamma-zero with `20*log10(DN)-83`. Mosaics can combine different acquisition dates. | Annual L-band background features. Preserve year and sensor, especially in cross-sensor comparisons. |
| [JRC Surface Water](https://developers.google.com/earth-engine/datasets/catalog/JRC_GSW1_4_GlobalSurfaceWater) · `JRC/GSW1_4/GlobalSurfaceWater` · `occurrence`, `seasonality` | Historical water frequency (%) and months of water from 1984–2021. The occurrence band has a nonstandard mask. Preserve missing coverage and use a documented permanent-water rule. | Historical water prior. For old training events, build a reference from imagery available before each event or the prior can leak future information. |
| [CHIRPS v3 daily satellite](https://developers.google.com/earth-engine/datasets/catalog/UCSB-CHC_CHIRPS_V3_DAILY_SAT) and [v3 daily reanalysis](https://developers.google.com/earth-engine/datasets/catalog/UCSB-CHC_CHIRPS_V3_DAILY_RNL) · `precipitation` | Daily rain in mm. Use v3 for recent data, check dates and latency, and reject or flag missing intervals. Keep the same version and product within an experiment. | Catchment-level accumulation over 1, 3 and 7 days. Rainfall recorded before forecast issue time can be a feature. For forecast lead time, use archived precipitation and discharge forecasts issued by then. |
| [Dynamic World](https://developers.google.com/earth-engine/datasets/catalog/GOOGLE_DYNAMICWORLD_V1) · `GOOGLE/DYNAMICWORLD/V1` · `label` and nine probability bands | Sentinel-2-derived land-cover classification. Use pre-event cloud-free probabilities and preserve low-confidence pixels. | Land-cover features explain different SAR behavior over crops, built areas and vegetation. Independent mapping is needed for flood labels. |
| [GHSL population](https://developers.google.com/earth-engine/datasets/catalog/JRC_GHSL_P2023A_GHS_POP) · `JRC/GHSL/P2023A/GHS_POP/2020` · `population_count` | Modeled population per cell for the 2020 epoch. For urban subsidence, train on InSAR time series checked against GNSS, leveling or independent observations. |
| [NASADEM](https://developers.google.com/earth-engine/datasets/catalog/NASA_NASADEM_HGT_001) and [Copernicus GLO-30](https://developers.google.com/earth-engine/datasets/catalog/COPERNICUS_DEM_GLO30_2024_1) · `elevation`, `DEM` | Elevation in meters. | [ALOS AW3D30](https://developers.google.com/earth-engine/datasets/catalog/JAXA_ALOS_AW3D30_V4_1) and [ArcticDEM](https://developers.google.com/earth-engine/datasets/catalog/UMN_PGC_ArcticDEM_V4_2m_mosaic) · `DSM`, `elevation` | Surface elevation. | [MODIS NDVI](https://developers.google.com/earth-engine/datasets/catalog/MODIS_061_MOD13A2) · `MODIS/061/MOD13A2` · `NDVI`, QA | Sixteen-day vegetation index. Multiply by 0.0001 and filter QA. | Seasonal vegetation covariate. |

Keep target snow when snow is the object of study. |

## NISAR and independent evidence

| Question | Input and target | What to publish |
|---|---|---|
| Where did floodwater expand? | [NISAR GCOV](https://nisar-docs.asf.alaska.edu/gcov/) calibrated powers or matched Sentinel-1 pair. Convert positive linear power to dB only when stored in linear units. Use identical frequency/polarization, QA and geometry. Independently labeled [Copernicus EMS](https://mapping.emergency.copernicus.eu/) polygons are preferred. [NASA VIIRS flood](https://lance.modaps.eosdis.nasa.gov/flood/) provides a dated, coarser cross-check with cloud and coverage limits. | Water candidate/validated mask, km² of detected water, date, overlap and unknown area. GDACS report points locate events, but provide no pixel labels. GFPLAIN and JRC river-hazard maps describe susceptibility or scenarios. MODIS Global Flood Database adds historic events with independent quality limitations. |
| How did an earthquake move the ground? | [NISAR GUNW](https://nisar-docs.asf.alaska.edu/gunw/) unwrapped phase, coherence, mask and look geometry, plus [USGS ComCat](https://earthquake.usgs.gov/data/comcat/). Use [ARIA](https://aria.jpl.nasa.gov/) published displacement where possible. Validate the product sign/reference before converting phase to line-of-sight displacement using wavelength. | Signed displacement along the radar line of sight, reference and date pair. Preserve spatial holes. ShakeMap reports shaking intensity separately. Physics-based aftershock forecasting, if ever evaluated, is a distinct task. |
| How is a glacier changing? | [NISAR GOFF](https://nisar-docs.asf.alaska.edu/goff/) tracks radar offsets over a pair. Use valid offsets, acquisition interval, look geometry and offset uncertainties. [ITS_LIVE](https://its-live.jpl.nasa.gov/) supplies independent velocity products. [ICESat-2 ATL15](https://nsidc.org/data/atl15) supplies gridded height change. [WGMS](https://wgms.ch/data_database/) supplies annual mass balance. | Publish speed (m/day or m/year), height change (m) and mass balance (m water equivalent) as distinct quantities. Height-to-mass conversion needs area, density and uncertainty. A velocity record alone cannot estimate melt. |

## Training sequence

1. **Flood detection.** Build an event manifest with UTC windows, footprint, product/granule IDs, orbit, validity masks, label source and time lag. Start with the change and terrain rules. Then train a LightGBM classifier on VV/VH, matched changes, incidence angle, slope, historical water and pre-event land cover. Designate unknown, permanent water and inundation explicitly. Hold out whole events and catchments, including an Algerian case with independent labels if available. Score flood IoU, precision, recall, area bias and coverage. Compare across rural, urban and vegetated scenes. Use a GPU U-Net only if sufficiently many independently labeled events show room for a spatial model.
2. **Flood forecasting.** Start with [GloFAS](https://global-flood.emergency.copernicus.eu/) or a basin discharge threshold. Archive issue time, valid time and lead time. Evaluate at 1, 3 and 7 days on held-out catchments using Brier score, reliability and false alarms. Train a boosted-tree calibration layer before testing a temporal neural network. A satellite map acquired after flooding validates detection and can verify a forecast, provided it is kept out of that forecast’s inputs.
3. **Earthquakes.** Ship ComCat plus validated GUNW/ARIA displacement first. If adding ML, detect unreliable or noisy pixels using coherence, connected components and terrain. Split by earthquake and acquisition pair. Measure error against independent displacement or GNSS projected into radar look geometry. No model of earthquake occurrence is included.
4. **Glaciers.** Start with per-glacier observations and linear/robust trends in repeat height or mass balance. Compare optical terminus segmentation or radar velocity against independent outlines/velocity and use glacier-level holdouts. For annual balance estimation, combine climate/terrain/seasonal snow features. Split by glacier and period, report MAE in m water equivalent and prediction intervals. WGMS records are sparse and uneven, so establish that a simple baseline generalizes before fitting neural models.
5. **Deployment.** Keep versioned manifests and numeric assets outside the request path. Publish compact layer metadata and scale/offset/mask information with each release. The map assistant reads the app’s published catalog and uses named actions to open records and switch modes. Science inference should run as a reproducible batch job and only published results should appear in the assistant’s answers.

For the demo, open Guelma and compare the dated NISAR views, then use the global catalogs to answer a question about another region. Show the processing manifest and validation metrics once a quantitative product is available.
